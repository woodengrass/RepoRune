# RepoRune (`rune`)

*Repository Understanding & Navigation Engine* — a repository-intelligence
system, independent of any specific coding agent, that gives an agent
deterministic code structure, persistent governance memory
(Decision/Constraint), expiring working Notes, and LLM-generated scope
summaries without re-exploring the repo on every new session.

See [ARCHITECTURE.md](ARCHITECTURE.md), [DATA_MODEL.md](DATA_MODEL.md), and
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for the full design and
its decision history; this file is only a quickstart.

## Install

Requires Python 3.12+ and git. From a built wheel:

```bash
pip install dist/rune-0.1.0-py3-none-any.whl
# or, with uv:
uv tool install rune
```

From source, for development:

```bash
git clone https://github.com/woodengrass/RepoRune
cd RepoRune
pip install -e .
```

This installs two console scripts: `rune` (the CLI) and `rune-mcp` (an MCP
server exposing the same functionality over stdio).

## Quickstart

```bash
cd /path/to/your/repo         # any git repository
rune init                     # creates .rune/, runs the first full index
rune status                   # project identity, index size, freshness
rune update                   # incremental re-index + semantic refresh (if configured)
rune doctor                   # environment/health diagnostics
```

Propose and approve a governance record (Decisions/Constraints always go
through a pending-proposal step; a human must approve them):

```bash
rune constraint propose no-bare-except \
  --content "never use a bare except:" --severity MUST \
  --persistence-mode persistent
rune proposal list
rune proposal approve <proposal_id> --by <your-name>
```

Notes don't require approval:

```bash
rune note add --category pitfall \
  --content "the retry loop swallows timeouts" \
  --why-persist "bit us in prod once"
```

Query what Rune knows:

```bash
rune search "postgres"                 # ranked full-text search
rune symbol-search --name get_user     # structured symbol lookup
rune scope-for path/to/file.py         # which scope(s) own this file
rune related-context --path-filter path/to/file.py   # one-call context bundle
rune check                             # working-tree diff -> affected scopes -> relevant constraints
rune bootstrap --mode hard             # global MUST rules + critical decisions
```

Commands that expose `--json` emit machine-readable output with a stable
`protocol_version` field on every payload; not every command supports JSON.

## Platform Notes

Rune emits CLI text and JSON as UTF-8 on Windows so non-ASCII repository
paths and memory content display correctly. On normal case-insensitive NTFS,
index include/exclude globs and supported source extensions are also matched
case-insensitively (for example, `SRC/APP.PY` matches `src/**` and Python).

`rune check` batches large working-tree change sets before querying SQLite,
so repositories with more than SQLite's parameter limit of changed files can
still retrieve relevant constraints.

### Semantic summaries (optional)

Scope summaries are generated by an LLM if configured in
`.rune/config.toml`'s `[semantic]` section. The API key is read only from
an environment variable, never from a project file:

```bash
export OPENROUTER_API_KEY=...   # or OPENAI_API_KEY, matching semantic.provider
```

`semantic.enabled = true` with an empty `semantic.model` is treated as a
configuration error (`rune doctor`/`rune update` will say so loudly), not
a silent no-op — set `semantic.enabled = false` if you don't want this
feature.

## MCP server

`rune-mcp` runs an MCP server (stdio transport) over the current
directory's Rune project, for any MCP-speaking agent host. Point your
host's MCP client config at the installed `rune-mcp` executable. See
`src/rune/mcp/server.py`'s module docstring for the full tool list and
what's deliberately not exposed (scope CRUD, proposal approval, and `rune
update` all stay human-driven).

## OpenCode adapter

`adapters/opencode/` is a separate TypeScript plugin for the OpenCode
agent host — see its own `package.json`/README-equivalent docstrings and
ARCHITECTURE.md §6/§6.1 for how it differs from the MCP server (it drives
proactive hard/soft bootstrap injection and per-tool-call scope
activation, not just on-demand tool calls).
